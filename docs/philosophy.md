# 设计哲学

> 这份文档写的是"为什么这样做"，不是"怎么做"。具体行为看
> [产品说明](../MANUAL.md)、[命令参考](cli.md)、[接口契约](api-v1.md)。
> 每一条都附了"因此我们拒绝了什么" —— 取舍比清单更能说明一个产品是谁。

## 1. 问题不是下载速度，是"取完之后"

2026 年的网络不缺带宽。真正让人半夜爬起来的是另一串问题：

拿到的东西对不对？存了几份？谁装的？装到哪？下次还要不要重下？
十个 agent 同时要数据时谁先跑？某个 agent 能不能写到别人的目录里？
失败之后是从头再来，还是接着上次？

现有工具（curl、aria2、rclone、网盘）在这段全是空白 —— 它们假设"传输完成"
就是终点，而 agent 场景里传输完成只是开始。

**因此我们拒绝了：**「更快的下载器」这个定位。速度是手段，可核对的落地才是目的。

## 2. 校验是一等公民，不是可选项

没有 sha256 的传输只能叫"搬字节"。所以：

- 下完**一定**算 hash；调用方给了 `--sha256` 就是**硬闸门**：不符即失败、文件丢弃。
- 没有 hash 时，我们**不给**"校验通过"这句话，只如实标 `trust=none` / `tofu-*`。
- 清单必须有 per-file sha256，否则拒绝安装。
- 签名（ed25519）解决的是另一半问题：`sha256` 证明"字节和某个 hash 一致"，
  签名才证明"这个 hash 是发布方给的"。**没有可信公钥就拒绝**（fail closed）。

**因此我们拒绝了：** 「先下下来再说」「校验失败也留着文件」「签名为可选提示」。

## 3. 内容寻址：一份内容，全机只存一份

`blobs/<xx>/<sha256>` + 落地硬链接。同一个模型被三个 agent 要，只下第一次；
删掉某个下载目录里的副本，缓存还在；同一个地址再取一次可能是**零网络**（`resolve`）。

**因此我们拒绝了：** 每个下载目录各存一份的"简单实现"，也拒绝了把缓存做成
"可随时清空的临时文件"（那会让秒传永远失效）。

## 4. 续传是状态，不是重试

段位图落盘（`.part` + `.json`），段大小 1 MiB 起：`kill -9` 之后最多丢一两段，
而不是丢一整段 5 MiB。跨进程用 `flock` 保证同一份 `.part` 只有一个写者。

**因此我们拒绝了：** 「失败了就重下」的粗暴重试，以及"把位图放内存"的做法。

## 5. 诚实边界：说清做不到的，比假装能做更值钱

`thunder://`、`ed2k://`、网盘分享页、NZB、DRM 流 —— **明确拒绝，并说明为什么**：
它们不是协议，是商业锁。BT v2-only 种子不支持、HLS 的分片由 ffmpeg 自己取、
云元数据默认拒绝、优先级不抢占运行中的任务、上传没有 S3 multipart……
全部写进 [已知边界](release-notes-0.24.md) 与 [安全模型](security.md) 的"残余风险"。

**因此我们拒绝了：** 用"即将支持"包装没做的事，以及把已知缺陷藏在代码注释里。

## 6. 最小权限：agent 不该拿到一把 shell

一个被 prompt injection 的 agent，可以让"下载器"去读云元数据、写
`~/.ssh/authorized_keys`、或者把 token 发到任意主机。这不是部署疏忽，
是产品必须在**进程内**拒绝的事：数据盒子不能变成 agent 的混淆代理。

- 出网：私网/回环/链路本地/CGNAT/元数据默认拒绝，**每一跳重定向重新检查**；
  云元数据是**独立开关**，不被"放开私网"顺带打开。
- 落地：`SKYGET_DEST_ROOTS` 之外不写；`..`、符号链接逃逸在 canonicalize 之后判。
- 上传：默认**全禁**，`SKYGET_UPLOAD_ROOTS` 显式圈地才可用（读本机往外送比 SSRF 更危险）。
- 身份：per-agent token，或者 Unix socket 的内核 uid（伪造不了）；带 token 只能碰自己的任务。
- 配额与并发：按 agent 的每日字节、并发上限、队列上限；满了明确回 429。

**因此我们拒绝了：** 「给 agent 一个 shell 让它自己调 curl」这种"简单"方案。

## 7. 预演必须和真提交走同一套代码

`skyget check` / `POST /check` 和真正的提交共用同一段 `preflight()`。
如果预演说"能过"而提交说"不行"，那预演就是负债而不是资产。

同理，错误码是契约：`error_code` 是机器读的，`next_action` 是人读的，
**不要求调用方解析中文**。

**因此我们拒绝了：** 为"预检"单独写一套更宽松的判定。

## 8. 可观测是运维面，不是日志考古

台账（谁、何时、多大、落在哪、hash）、事件流（可重放、带 `seq`）、阶段耗时
（`probe`/`transfer`/`verify`/`land`）、`/metrics`、`doctor`、`top`、`statusline`。
出问题时能回答"谁在下什么、卡在哪、为什么失败"，而不是去 grep 一堆日志。

**因此我们拒绝了：** 只有 stderr 的进度输出，以及"失败就一句 unknown error"。

## 9. 一台机器上多个 agent 是默认场景

公平队列（谁跑得少谁先）、per-agent 策略覆盖（落地根/白名单/上传根/并发）、
优先级（interactive > normal > batch，不抢占但先排队）。
CLI 不带 `--as` 时保持独立下载 —— 人不该为了下一个文件被迫先起一个服务。

**因此我们拒绝了：** 「一个 agent 一个下载器」（缓存、并发、台账全部分裂）。

## 10. 不做的事，不做

- **不发 npm 包**：常驻 daemon + 四个原生二进制 + systemd 单元，和 npm 的模型错配。
- **不做 `curl | sh` 安装**：供应链面最大、收益最小。
- **不做跨机共享缓存**：局域网分发用 BT 或 `export/import`，不发明"带 token 的公共缓存服务器"。
- **不绕过网盘/迅雷会员/DRM**：那不是技术问题，是别人的商业模式。

**因此我们拒绝了：** 为了"看起来功能多"而收编一堆不该由数据盒子承担的事。

## 11. 对源站礼貌：快不等于猛

我们是别人服务器上的一个客户端。所以并发默认按体积 **4–16**（不是 128）、
同一主机的连接数有全局上限、被 429/503 时就退（**按服务器给的 `Retry-After` 等**，
最多 5 分钟）、UA 诚实、不伪装浏览器、不发伪造 Referer。

**因此我们拒绝了：** 「把连接数开到最大」这种"性能优化"——它把成本转给源站，
代价是所有人的下载变慢，以及某天整个 IP 段被拉黑。

## 12. 测试即证据，文档不许说谎

每条对外承诺都尽量对应一个测试：`docs/conformance.md` 是"契约 → 证据"的映射表。
发版清单要求"安全边界变化必须同步 `security.md`，包括残余风险，不许只写已修复"。

**因此我们拒绝了：** 「文档写得好听、代码没覆盖」的常态。

---

**一句话总结**：这个产品赌的是"agent 会越来越多、越来越不听话"，
所以把可核对、可限制、可观察这三件事做进内核，而不是交给调用方的自觉。
