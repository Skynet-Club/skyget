# 复盘：这个下载器积累下来的东西

不是项目总结，是**下次开工前该读的那一页**。52 个提交、0.10 → 0.18，把踩过的坑按
「症状 → 根因 → 怎么发现的 → 以后怎么防」归了类，把定下来的界面规矩写成了能照着做的条目。

---

## 一、一句话结论

这个项目真正攒下的不是「支持直链 + 种子 + 切片」这三件事 —— 那是几周就能抄的。
攒下的是三条**别人不容易做到的习惯**：

1. **每个数字都有出处**：说快了多少就给前后两个帧率/CPU/字节数，说不出处就写「没测」。
2. **每次「应该好了」都要真跑一次**：下错目录、进度归零、按钮点不动这三类 bug，
   全是看代码看不出来、一跑就露馅的。
3. **不能靠人手点的地方，就把判定抽成纯函数 + 单测钉住**：这台机器的合成点击
   到不了 Wayland 客户端，所以每个交互背后都有一层可测的判定。

## 二、UI 风格：定下来就不动的那些

来自 `docs/gui-style.md`，这一版又验证了一遍（越界的地方都被指出来了）。

| 规矩 | 为什么 | 代价 / 边界 |
|---|---|---|
| **全直角**，不用圆角 | 圆角在小尺寸下会糊，而且不同主题圆角不同，看起来像「借来的组件」 | 弹层、按钮、输入框都要显式 `rounding=0` |
| **六条缝都是 1 物理像素**（手画，不靠留白） | 留白做不到「一条线」的确定性；缩放后 1 逻辑像素会变 2 物理 | 要按 `pixels_per_point` 换算，代码里到处是 `1.0/ppp` |
| **颜色只做分类，不做强调** | 一旦用颜色强调，界面就开始「抢注意力」，两次之后满屏都是重点 | 悬停只提亮（FAINT → TEXT），不画背景块 |
| **图标手画 16 网格、1.25 线宽** | 字体符号在不同环境缺字，而且粗细不受控 | 每个图标 15~40 行 `painter` 代码（暂停/继续/取消/重试/删除/文件夹） |
| **工具栏只放图标**，不混文字按钮 | 图标+文字混排会让一行高度不齐、视线跳 | 要说明的地方用 tooltip（悬停才出现，不占地） |
| **状态由按钮本身承担**，不单列一列 | 「可用/不可用」已经由灰不灰说清了，再列一列是重复 | 灰掉的按钮必须同时说明为什么灰（一句话，不是光灰） |
| **列表定宽列** | 数值从 `9 B` 涨到 `900 MB` 时列不能跳，否则整张表在抖 | 数字列右对齐 + 固定宽度，中英混排要按显示宽度算（ASCII=1，其余=2）|
| **详情卡「有值才出现」** | 一条失败的任务不会硬撑显示空的「校验」「线路」；少几行比几行「—」好读 | 每行都要判空，代码里 `if !s.is_empty()` 到处都是 |
| **不在界面上堆输入框** | 改目录一年两次，常驻输入框就是把一次性的东西摆在最显眼位置 | 改成「一个小图标 + 点开弹层」 |

**这一轮新学到的两条**：

- **控件挪位置要连带改宽度算式**。把「保存目录」从地址框左边挪到「下载」右边之后，
  地址框的宽度必须先把那个控件的宽度量出来再扣 —— 否则要么挤掉控件，要么控件顶出屏幕。
- **弹层要贴着控件出现**，而不是固定坐标。而且三种进法（点开 / 快捷键 / 验收旋钮）
  必须都贴着：所以按钮的矩形要**每帧**记下来，不能只在点击那一刻记。

## 三、交互设计：七条原则（每条都配一个反例）

1. **点了就得有反应，或者明白说为什么没有。**
   反例：保存目录按钮点了没反应 —— 其实是同一帧里「开了又立刻关了」。
   现在的做法：能操作的按钮一定亮；不能操作的画灰 + 悬停一句话；实在要静默的，先写日志。

2. **说人话，一句话给结论 + 下一步。**
   反例：22 段逐行念「请求失败：超时」，读完还是不知道该干什么。
   现在：全倒在同一件事上就一句「连不上源：5 次连接全失败了（25 秒）。已下的留着，
   重跑会接着下 —— 这是网络问题，不是源坏了。」；确实是某几段坏了，才按段号一段一行。

3. **不假装成功。** 对不是本服务在跑的任务 `pause` 回 **409** 并说明「这条不是这个服务在跑，
   停不了它」。比回 200 然后什么也没发生要好。

4. **数字要么是真的，要么写「—」。** 尺寸未知就 `—`，绝不填估算值。
   失败时也要保留「已经下到多少」（曾经失败一律显示 0 B / 110MB，盘上明明有 24MB 分片）。

5. **关窗口不等于掐下载。** 下载在守护进程里，窗口只是它的脸；重开 700ms 内贴回台账。

6. **看不见的过程要说清楚。** 秒传要标「本机早有这份内容，一字节没下」；
   卡住要标「45 秒没有一个字节进来」；谁发起的要标（人 / 命令行 / 某个 agent）。

7. **一次性的东西不占常驻位置。** 改目录、清缓存这类低频操作走弹层或命令行，
   常驻位置留给高频的（地址栏、列表、五个播放器控件）。

**播放器式控制条的具体设计**（用过一次就知道对）：五键位置固定、不可用变灰而不移位、
空格键 = 当前那条的主动作。手指不会因为按钮跑位而点错，这是「精美」的实际含义。

## 四、Bug 复盘：八类，按「有多难发现」排

| # | 症状 | 根因 | 怎么发现的 | 以后怎么防 |
|---|---|---|---|---|
| 1 | **按钮点了没反应** | 同一帧里先打开弹层、再判定「点在弹层外面」→ 立刻关掉 | 用户报「点不了」，读代码发现两段逻辑各自都对 | 把「该不该关」抽成纯函数，先写单测把「同一帧不关」钉住，再改调用处 |
| 2 | **下到一半断电/崩溃，永远停在「下载中」** | 守护进程重启后没人对账：台账说 running，但没有线程在下 | 主动 kill -9 试的 | 启动先对账（running→interrupted + 写清原因），最多两条自动接着下，崩溃循环则不接 |
| 3 | **源卡死 = 永远「下载中」** | 请求没有超时上限，五个连接挂着、一个字节不来 | 用户报了那条 GitHub 源，查台账发现挂了一小时、字节不动 | 请求 90 秒上限 + 45 秒「卡住」提示；卡住也是一种状态，得说出来 |
| 4 | **设了不生效**（保存目录） | 命令行那条路径自己写死了默认目录，没走设置 | 设完之后真下了一个 11MB 文件，看落点才发现 | 一条设置只留一个入口（`settings::dest_dir()`）；端到端检查盯「落点」而不是「设置文件」 |
| 5 | **下完了还在走 / 攒出 (1)(2) 副本** | 重试走 `unique_path`、进度条不清零 | 用户问「这条已经结束了为什么还在走」 | `Task.rerun` 标记 + 重试落回原路径；进度条以台账为准 |
| 6 | **一条任务能跑两遍，文件会烂** | 重复派发时 `running` 表没查，两个线程写同一份 `.part` 和同一张位图 | 代码审查时推演并发路径发现的 | 派发前查 `running`，已有就 409；这类「两个线程写同一个文件」要当 P0 |
| 7 | **空转把 CPU 烧掉、Dock 一直抖** | ① 心跳无条件写 `updated_at`，卡住的任务每 900ms「变动」一次 → 界面以为有事发生；② 轮询每次成功都 `request_repaint` | 先量帧率（196 帧/秒）和 CPU（29%），再定位到具体行 | 写库只写「真的变了」；重绘只在有变化时求；加了 `SKYGET_GUI_DEBUG` 每 5 秒写一行帧率+「谁在求重绘」 |
| 8 | **接口说了假话** | 请求体超 1MiB 静默截断 → 报错指向「缺字段」；`POST /jobs` 回 200 让人以为下完了；`route()` 先把 `?` 切掉 → `since`/`limit` 从来没生效 | 写脚本逐条打接口看状态码和字节 | 状态码说实话（202/413/404/400）；路由匹配用干净路径、解析参数用完整路径；接口要有脚本化验收 |

**还有一组「环境坑」，跟代码无关但一样耗时**：

- **Linux 进程名只有 15 字节**：`skynet-downloadd` 被截成 `skynet-download`，和界面一字不差 ——
  `pkill -x skynet-download` 会把守护进程一起杀掉。守护进程现在叫 `skygetd`。
- **pid 文件只看「活着」不够**：pid 会被重用，要核对 `/proc/<pid>/cmdline` 是不是自己，
  否则会给不相干的程序发 SIGUSR1（默认动作是终止）。
- **单实例锁会让人以为「跑不起来」**：旧进程占着锁，新进程发完唤醒就退出（还有一个坑：
  它就是 20:41 那次截图失败的真正原因）。
- **Wayland 没有「隐藏窗口」**：winit 的 `set_visible()` 是空实现，只能最小化；
  合成点击（XTEST）到不了 Wayland 客户端，所以每个交互都得留一条可测的判定或验收旋钮。
- **图标编进二进制**：`include_bytes!` 的图换了必须重编，否则顶栏还是旧 logo。
- **矢量源不是正方形会被拉变形**：`-w 512 -h 512` 会硬拉，1.7% 的压缩肉眼能看出箭头歪。
  先按宽渲染再放正方形画布居中。

## 五、开发方法：这一版最值钱的部分

1. **先量后改，改完再量**。每条优化都有前后两个数：
   闲置帧率 196/s → 0；空闲 CPU 29% → 0.35%；秒传 102MB 从 10.8s → 0.12s；
   重启接续 53.9MB 处 kill -9 → 3 秒后下完（102393700 字节）。
2. **一次真跑胜过十次读代码**。第 4 类 bug（设了不生效）就是读代码读不出来的。
   所以规则是：**新功能落地前，必须有一次「用户视角」的端到端动作**（下一条真的、设一次真的）。
3. **能自己证明的产品才值得信**。`skyget selftest` 12 条行为断言（进程内假服务器，
   五秒、不联网），它自己抓出过三个真 bug（暂停进度归零、429 判死、有 sha 仍问服务器）。
   `verify --deep` 连「缓存块被改了一个字节」都报得出来。
4. **改 bug 先要根因（file:line），再谈修法**。修完在 commit 里写清「为什么只有真跑才会现形」——
   下一任（包括三个月后的我）看 commit 就能重建现场。
5. **人手点不了的地方，把判定抽出来测**。`popup_should_close(opened_pass, now_pass, click, area, opener)`
   这种签名丑但有用：它让「同一帧不许关」变成一条断言，而不是一段没人敢动的 UI 代码。
6. **CRUD 之外还要测「坏」**：撒谎的镜像、假 Range、429、慢滴、截断、断电、并发写 ——
   正向路径跑通只说明能演示，反例跑通才说明能用。

## 六、做错的决策（记下来免得重犯）

- **一开始把下载线程放在界面里**：于是「关窗口 = 掐掉下载」，绕了一大圈才拆出守护进程。
  教训：**生命周期的归属要在第一版就想清楚**（谁在下 vs 谁在显示）。
- **信任级别被缓存捷径覆盖成 `pinned`**：把「发布方给的 hash」说成「你给的 hash」= 撒谎。
  教训：**分级字段只能由调用方给，不能被底层顺手改写**。
- **`list(1000)` 再筛活跃任务**（清缓存时）：台账超过一千条就会误删活任务的缓存块。
  教训：**筛选条件要下推到查询里，不要「取一批再筛」**。
- **「多久没碰过」只看 mtime**：天天在用的块和第 31 天没人理的块一样老，清的是常用的那个。
  教训：**判据要写清「碰过」的定义**（这里是 max(mtime, atime) + 命中时 touch）。
- **早期版本用 `wl-paste` 每 600ms 读剪贴板**：每 600ms 一个新 Wayland 客户端，
  gnome-shell 每秒处理一次半，Dock 图标一直闪。教训：**轮询外部进程的代价要按「新建客户端」算**。

## 七、下一个版本该做什么（不是更大，是更深入）

1. **多源 + Metalink**：同一 sha256 的 N 个地址，一条断了别的补上。价值不在快，在**可被反例验证**
   （一条镜像撒谎 → 必须拒绝落地）。见 `docs/protocols.md`。
2. **`--header` / `--auth`**：把已经能下的私有地址（公司制品库、S3 预签名）真的下下来。一天的量。
3. **界面内存**：190MB（200 条台账时）没查清花在哪，先查再改 —— 不要因为「看着大」就动手。

明确不做：多支持几种协议、多开几个窗口、把界面做得更「满」。那是更大。
